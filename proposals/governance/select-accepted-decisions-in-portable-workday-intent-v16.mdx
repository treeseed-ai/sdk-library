title: Select accepted decisions in portable workday intent v16
request: "Refine the existing SDK decision-selection contract instead of adding
  a parallel feature. Export normalizeWorkdayIntent(intent: WorkdayIntent):
  WorkdayIntent from src/operator-contracts/workday-lifecycle.ts. It returns a
  fresh object reconstructed in this canonical property order: schemaVersion,
  teamId, profileId, projects, executionMode, startsAt, endsAt, durationSeconds,
  objectiveFilters, planningOnly, proposalIds, decisionIds, agentSelection,
  allocation. It retains every present allowed field, trims decision IDs before
  validation, rejects empty IDs at decisionIds[index], rejects duplicates after
  trimming at decisionIds[index], sorts IDs lexically, and preserves absent
  decisionIds as undefined. Remove operatorConstraints from WorkdayIntent.
  validateWorkdayIntent is the top-level strict runtime-key boundary: any other
  own enumerable key produces workday_intent_unknown_field at that exact
  top-level key path. The spelling-sensitive forbidden matrix is
  operatorConstraints, graph, executionGraph, executionPlan, capacityPlan,
  demand, assignment, source, role, estimate, reservation, usage,
  providerSelection, provider-selection, and provider. Nested agentSelection and
  allocation keys remain owned by normalizeWorkdayAgentSelection and
  workdayAllocationOverridesSchema validators, whose diagnostics retain their
  existing nested paths; this proposal does not duplicate nested validation.
  WORKDAY_PLAN_OPTIONS in selection-commands.ts owns one --decision option,
  workdayIntentInputs in canonical-command-tree.ts owns one decisionIds binding,
  and TREESEED_COMMAND_TREE_V1 workdays plan and workdays schedules start each
  emit exactly one structurally equal --decision option by reusing
  WORKDAY_PLAN_OPTIONS; execution graph --decision is an unrelated read filter
  excluded from this assertion. The SDK proves deep equality and JSON.stringify
  equality only for inputs that differ in top-level WorkdayIntent property
  insertion order and decisionIds order. Nested agentSelection and allocation
  insertion order is outside this normalizer and remains owned by their existing
  canonicalizers and validators. WorkdayPreflightReceipt, WorkdayStartReceipt,
  WorkdaySettlement, WorkdaySelectedDemand, and their selectedDemands,
  assignments, reservations, providerReceiptRefs, and settlement fields remain
  read-only portable receipt representations; they are forbidden only as
  caller-authored WorkdayIntent inputs. No external API implementation behavior
  is claimed or tested. Exact high-level mapping is profile=profileId,
  projects=projects, timing=startsAt/endsAt/durationSeconds,
  custody=executionMode, planning=planningOnly/proposalIds/agentSelection,
  acting authority=decisionIds, objective=objectiveFilters, and
  allocation=allocation; no separate communication field exists in
  WorkdayIntent. The immutable inventory identifier
  sdk-workday-contract-inventory-v1 is normative for downstream Architecture and
  implementation results. Clarification: workdayIntentInputs contains exactly
  one decisionIds binding; TREESEED_COMMAND_TREE_V1 exposes that binding exactly
  once in workdays plan and exactly once in workdays schedules start, and
  execution graph is excluded. Only each descriptor's --decision option object
  must be structurally equal to the canonical WORKDAY_PLAN_OPTIONS --decision
  member; the complete options arrays are intentionally different. Before
  trimming, every decisionIds element must be a string; a non-string element
  yields workday_intent_decision_invalid at decisionIds[index]. Empty-after-trim
  and duplicate-after-trim values yield their own indexed diagnostics. The
  inventory table must contain one row per named symbol with exact path and
  lines, public export path or explicit none, every repository consumer found or
  explicit none, and exactly one keep/delete/duplicate disposition."
summary: Prove the SDK can express high-level decision-governed execution while
  keeping all derived execution state API-owned.
