The SDK is structured as a portable contract and typed remote-client package: per [README.md](/workspace/project/README.md:1), it owns versioned control-plane/operator contracts, standards contracts, and remote clients for TreeSeed, TreeDX, and capacity-provider access, while explicitly excluding persistence, scheduling, repository mutation, deployment, provider runtimes, and server-side workflows. Its public surface is intentionally subpath-based rather than a root catch-all export, which preserves explicit package boundaries and compatibility expectations ([package.json](/workspace/project/package.json:1), [README.md](/workspace/project/README.md:56)). The repository’s lint/verification entry points are `npm run lint` (`build:dist`), `npm test` (`vitest` contract suite), and `npm run verify:direct` (`release:verify`) as defined in [package.json](/workspace/project/package.json:18). The main CI verification workflow runs `npm run verify:direct` in [`.github/workflows/verify.yml`](/workspace/project/.github/workflows/verify.yml:1), and that release verification chains `check:file-lengths`, `check:file-architecture`, and `scripts/packages/release-verify.ts` through the same script graph in [package.json](/workspace/project/package.json:18).
