I read the SDK core objective at the exact TreeDX path `objectives/core.md`. It defines the SDK as the platform substrate for TreeSeed content, control-plane state, graph-first context, workflow orchestration, reconciliation, hosting, package workflows, shared contracts, and TreeDX integration, and it sets that scope as the north star for package-local planning and execution. It also draws the package boundary explicitly: SDK owns portable primitives and shared contracts, and it must not take on higher-layer responsibilities like UI routes, provider execution, backend API ownership, or turning TreeDX internals into product semantics.
