From those files, the SDK architecture is package-scoped and explicitly subpath-oriented rather than root-export oriented. `README.md` states the package is TreeSeed’s “portable contract and remote API package,” and `package.json` reinforces that by exporting bounded surfaces such as `./operator-contracts`, `./control-plane-client`, `./treedx`, `./treeai`, `./standards`, `./platform`, `./knowledge`, `./feedback`, `./agent-capacity`, and `./graph/context-query-contracts`, while intentionally omitting a root `src/index.ts`. That is an architectural boundary: consumers import a specific contract surface, not a catch-all SDK namespace.

The central spine is the control-plane contract layer. `src/operator-contracts/index.ts` aggregates the command tree, workday lifecycle/profile, OAuth types, MCP input contracts, communication/inbox contracts, seed bundle, and control-plane operation catalog. `src/entrypoints/clients/control-plane-client.ts` shows the runtime side of that spine: a typed HTTP client that validates path/query/body against authoritative operation bindings before dispatch, handles OAuth device/refresh flows, and normalizes control-plane server profiles. That indicates the SDK owns typed transport and contract enforcement, not backend implementation.

Around that spine, the package splits into bounded domains:

- `src/treedx/*`: a TreeDX proxy facade. `src/treedx/client.ts` binds only the TreeDX-related subset of control-plane operations, and `src/treedx/contract.ts` validates that TreeSeed’s proxy mapping stays aligned with the authoritative upstream `@treeseed/treedx` OpenAPI contract while excluding private upstream operations. This is a deliberate boundary: TreeDX remains upstream and remote; the SDK exposes only the TreeSeed-governed proxy surface.
- `src/treeai/*`: the same pattern for TreeAI. `src/treeai/contract.ts` records adopted upstream release/digests and validates operation mapping into the control-plane catalog.
- `src/standards/*`: compatibility and release evidence machinery for TypeScript, OpenAPI, and MCP. `src/standards/index.ts` exports canonicalization, compatibility attestation, composition, contract bundle, manifest, and portfolio-entry logic, which matches `treeseed.package.yaml`’s produced standards artifacts and release-gate checks.
- `src/platform/*`: platform contracts, schemas, inventory, workset, and verification helpers. This looks like portable platform-state modeling, not runtime orchestration ownership.
- `src/content/*` and `src/graph/*`: shared content-model and graph/context-query contracts. `src/content/contracts.ts` defines portable content model references and actions; `src/graph/context-query-contracts.ts` defines declarative context query compilation into SDK graph request shapes.
- `src/capacity-provider/*` and `src/agent-capacity/*`: provider-facing contracts, validation, sandbox contracts, ontology, and agent/workday/capacity records. This is contract and policy surface area, not provider execution.

`treeseed.package.yaml` confirms the top-level architectural intent explicitly: `projectArchitecture.topology: package_only`. It also shows the SDK produces immutable standards artifacts from its own sources and consumes authoritative TreeDX/TreeAI service contracts, which fits the README boundary statement that the SDK does not own persistence, scheduling, deployment, provider runtimes, or server-side workflows. Evidence supports describing the package as a **portable contract-and-client substrate**: one package that publishes versioned contracts, compatibility standards, and typed remote clients for the TreeSeed control plane and proxied upstream services, while keeping implementation authority outside this repository.
